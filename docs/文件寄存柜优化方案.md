# 文件寄存柜优化方案与交互设计

日期：2026-11-15。基于 `dev` 工作区代码核对。**状态：用户已确认管理工作台及功能规则；现已实施并通过本地功能验收，Windows 候选包已生成，详见《文件寄存柜实施记录》。**下文现状表保留设计阶段的问题诊断，当前行为以实施记录和 V2 契约为准。

本方案补充并修订《文件寄存柜设计.md》的体验与状态规则。旧文档中“取完立即焚毁”“吊销分享”等描述，以实际代码核对和本次确认后的新规则为准。

## 1. 目标与推荐方向

把首页改为可直接处理文件的工作台：上方提供“寄存文件 / 取件”，下方展示自己的寄存记录；同时能看懂服务是否可用、文件还可不可以取、剩余多少名额、清理是否完成。

提供两种效果图方向，功能规则相同：

| 方向 | 首页组织 | 适合 | 建议 |
| --- | --- | --- | --- |
| 管理工作台 | 紧凑操作栏、连接状态、筛选与文件列表 | 已有多个文件、经常查看状态或管理分享 | **推荐作为默认** |
| 快捷交接 | 两个适度大小的寄存/取件入口、首次使用引导、最近寄存 | 偶尔使用、希望入口非常直接 | 保留为备选，不建议增加用户永久切换布局的负担 |

沿用御钥师的蓝紫色、浅色背景、普通圆角按钮与文件列表语言。去掉售货机式厚底座、强高光和巨大“寄 / 取”字样。主要动作始终用完整动词，危险动作不与“取件”并排争夺注意力。

## 2. 现状核对与需修正的问题

以下是代码层面的发现，未操作真实存储桶或分享服务。

| 现状 | 使用上的问题 | 设计处理 |
| --- | --- | --- |
| 首页两个大按钮，配置独立在角落；空态只有“还没有寄存” | 不知道是未配置、加载失败，还是确实没有文件 | 分开呈现加载、未配置、空列表、连接异常 |
| 桌面选择文件后直接调用上传 | 用户尚未核对文件、有效期、次数就提交 | 选择只加入待寄存区，明确点击“开始寄存”才上传 |
| `finishPut` 先寄存成功，再生成分享，两步共用外层错误 | 分享失败可能被理解成上传失败，再次上传产生重复文件 | 展示“文件已寄存，分享未完成”，只重试分享 |
| 取件用自绘数字键盘与六个展示格 | 桌面键盘、粘贴、自动填充和错误定位不自然 | 使用单个真实输入框，支持空格与全角数字规范化，不自动提交 |
| `index_by_code` 在当前工作空间元数据中查找六码 | 容易误以为任意他人六码都可以取 | 区分“我的寄存：六码”和“收到的分享：完整链接 + 六码” |
| Worker `revoke()` 调用 `burn()` 删除对象；客户端却清空 share 后保留寄存项 | **“吊销分享”实际可能连寄存文件一起删除** | 必须拆分“停止分享”和“删除寄存文件”；在服务端支持前不能只改按钮名称冒充安全撤销 |
| 共享取件先处理计数/清理，再解密；自取在目标路径最终写入前记账；存入保险库是第二次调用 | 下载中断、解密失败、改名失败或入库失败时，最后一次可能已被消耗 | 新增独立领取操作与可恢复状态，先选目标，正确区分交付、保存与名额结算 |
| Worker 在发送数据前扣减，最后一次流结束或失败均尝试删除 | “失败不扣次数”“保存成功后才销毁”并非当前可承诺的行为 | 提供领取会话与原操作恢复，避免将网络重试变成再次领取；明确浏览器保存的可观测边界 |
| 已分享状态轮询主要检查链接存活，次数不是完整权威同步；自用次数在客户端元数据内 | 多设备并发时不能据此承诺严格一次领取 | 有限次数统一由服务端原子分配；UI 显示更新时间，离线不伪造准确余量 |
| 列表查询同时扫除过期项，删除失败保留，成功后条目消失 | “已过期”与“已从云端删掉”被混为一谈；用户找不到结果 | 分开显示访问状态、清理状态和简短结束记录 |
| `buildOpts` 把无效自定义输入强制变成 1 | 用户以为设定生效，实际规则被悄悄改变 | 正整数校验并就地报错，阻止提交，不静默改值 |

证据位置：

- [ToolsLockerPage.tsx](../app/src/pages/tools/ToolsLockerPage.tsx)：`buildOpts`、`finishPut`、`putFromPath`、`pullToDisk`、`pullToVault`、首页/取件弹层。
- [commands/locker.rs](../app/src-tauri/src/commands/locker.rs)：`sweep`、`index_by_code`、`write_pull`、`locker_pull`、`locker_revoke_share`。
- [file-locker.js](../app/src-tauri/assets/file-locker.js)：`SQL_PULL`、`revoke`、`pull`、`streamCipher`。这是内嵌构建产物；实施时应通过 `scripts/embed-locker-worker.mjs` 追溯原始 Worker 源码，不直接仅修补该产物。

## 3. 信息架构与首页

页面顶部：标题“文件寄存柜”；说明“临时加密存放，到期或名额用完后停止取件并清理”；右侧“连接设置”。不把存储桶、Worker、令牌字段挤入日常寄存流程。

连接提示始终可见：分别显示“云存储”和“取件服务”的就绪/未配置/异常状态、上次检查时间。需要配置时给出就地入口；检查中显示检查中，不能先显示成功。后台刷新不覆盖用户正在填写的配置草稿。

主区域：

- “寄存文件”为主按钮，“取件”为次按钮。
- “进行中 / 已结束”筛选，搜索名称；无结果提供清空搜索。默认按最近寄存排序；异常项显示可执行的处理入口。
- 每行显示文件名及大小、用途（自己取用/对外分享）、剩余时间、领取名额、状态与动作。
- 正常行突出“分享”或“查看详情”；到期项提供“查看清理状态”，失败项提供对应的局部重试。取件码与完整分享链接不铺在列表里。
- 大于一天用“6 天后到期”，不足一天用“18 小时后到期”；详情补绝对时间及本地时区。无需全列表每秒跳动的倒计时。
- “已结束”保留最小加密元数据和原因，建议本机保留 7 天、可清空；不保留取件码或内容密钥。这是新增能力，不把当前删除墓碑当成已有历史列表。

空态区分：未配置显示两步连接引导；已就绪且无文件显示拖放区域和“寄存第一个文件”；加载失败保留原列表和重试；真实空列表才显示“暂无寄存”。

## 4. 寄存流程

采用独立任务工作区，保留返回入口与原列表筛选。桌面为表单 + 右侧规则摘要，移动端上下排列。避免在多层弹窗之间穿梭。

1. **选择文件**：本地选择、拖入，或“从文件保险库选择”。本期每次一份，保持现有 **100 MiB** 上限；显示文件名、大小、来源，允许替换/移除。取消选择不改变既有草稿。
2. **设定规则**：名称默认原文件名；默认 24 小时、1 次领取；用途默认“自己取用”，用户显式选择“分享给他人”。分享用途会检查服务，不能悄悄降级为自取。
3. **核对摘要**：例“24 小时内可领取 1 次；到期或名额用完即停止新的取件，随后清理云端文件”。显示最终到期时间；计时从寄存完成起算，不包含排队和上传时间。
4. **开始寄存**：点击一次后锁定本次参数、生成操作 ID，展示“加密 → 上传 → 登记 → 完成”。能获得字节数才显示百分比；否则展示当前阶段与字节，不编造进度。
5. **完成与交接**：自己取用展示取件码；分享用途展示“完整链接 + 取件码 + 截止时间”的交接卡，并提供单独复制链接、码及现有二维码能力。合并复制可用，同时提示转发整段意味着转发访问权限。

高级项：1 小时/24 小时/7 天/30 天/自定义；1 次/3 次/自定义/不限次。永久和不限次藏在高级规则内，组合使用时提醒这是长期存放，更适合文件保险库，不默认选中。自定义时长与次数必须为范围内整数。

部分成功：上传与登记完成、分享失败时，标题仍为“文件已寄存”，次级告警为“分享暂未生成”；提供“重试分享”和“稍后处理”。已取得寄存 ID 后不得以“重新上传”作为默认恢复。

离开与取消：未提交草稿可返回；执行中返回不会偷偷取消后台任务；取消请求须有后端确认，显示“正在取消/正在清理”，最终确认后才显示取消。尚不支持取消的阶段明确告知“正在完成登记”，不提供无效的取消按钮。

## 5. 取件流程与领取次数

入口分两类：

- **我的寄存**：当前解锁工作空间的六码选择器，支持 `123 456` 和全角数字；列表中的“取回”免输自己的码，但保留既有机密访问验证策略。
- **收到的分享**：完整分享链接和六码；保留 URL 的 `#` 后解密信息。只有六码不能全球查找文件。仅解析不会打开第三方页面或发出领取请求。

流程：输入 → 查询并验证 → 展示可信文件信息、截止时间及剩余名额 → 选择“保存到本地 / 存入文件保险库” → 点击“领取并保存” → 状态结果。查询/复制/看详情均不消耗名额。取消系统保存对话框不得启动领取。

文件信息来源必须说明：发送方文件名来自链接时只是显示信息，不是已验证元数据；必须净化路径。预查询接口要验证码并实施限速，不得泄露任意文件的名称、大小或是否存在。

### 统一计数与失败恢复

不能仅在前端把扣减挪到“保存成功”回调：客户端不回执也可能已经拿到内容；网络断开后，服务端也不能判断浏览器是否完成了保存。

建议把文案统一为“可领取次数/领取名额”，并实施：

1. 服务端原子预留名额，绑定原始 operationId、文件版本、领取会话；同 ID 重入返回原操作。
2. 尚未开始内容交付的预留，可在明确取消或租约到期后释放。
3. 一旦开始交付，失败/超时不能自动释放并创建新领取。原会话提供限时、限次数的继续/重新交付能力；暂定 15 分钟、最多 3 次，需在协议评审中验证并可配置。
4. 本机端先写入受控临时文件，校验、同步写入并原子落到目标，或直接在后端完成保险库入库，再确认结果；不再把取出内存字节和入库分成两个不关联的操作。
5. 浏览器确认解密与发起保存后可标记“已交付”，但**不能宣称服务端已证明用户保存到磁盘**。若 ACK 丢失，保留“结果待确认”与同会话恢复，不重新消耗第二个名额。
6. 最后一个名额被占用后拒绝新的领取；在原会话完成或恢复窗口截止后清理。明确手动删除可中止恢复，删除确认中说明这一点。

有限次数的自用寄存也需要同一权威服务，不能由多个设备各扣本地计数。只配置云存储时可提供“基础自用寄存”，仅不限次；有限次数及网页分享在取件服务可用后开放。已有旧项显示“旧规则”，迁移前不可暗示已获得新的一次性保证，也不自动增加剩余次数。

这是需要服务协议升级的设计目标，**当前实现不具备以上领取会话和查询/结算接口**。新 UI 的相关承诺必须与后端一起上线；旧 Worker 版本不兼容时明确提示升级，不能静默走旧计数。

## 6. 分享、删除与生命周期

“停止分享”只禁用该分享入口，保留寄存文件供本人取用；重新分享生成新链接，旧链接保持失效。不能撤回已经下载的副本；已经开始的交付可能无法中止，界面确认中说明作用范围。

“删除寄存文件”立即阻止新的领取，失效所有链接，并开始删除远端对象及本地解密材料。确认框显示文件名、链接影响与不可恢复含义。删除失败保留可重试的清理记录，不能提前宣称“已彻底销毁”。

生命周期分成独立维度，避免一个状态字段混用：

| 维度 | 状态示例 | 用户看到的动作 |
| --- | --- | --- |
| 寄存任务 | 待开始、加密中、上传中、登记中、完成、结果待确认、失败 | 开始、查看进度、查询原操作、局部重试 |
| 可访问性 | 可领取、名额已预留、已到期、次数用尽、已手动禁用 | 领取、查看处理中原因、查看结束原因 |
| 分享入口 | 未创建、创建中、已启用、创建失败、已停止 | 创建分享、复制交接信息、重试分享、重新分享 |
| 清理 | 不需要、等待清理、清理中、清理失败、已清理 | 查看状态、重试清理 |
| 同步 | 已确认、刷新中、离线/状态待确认 | 刷新、检查连接；不展示过时数据为实时值 |

到期由服务端拒绝访问；删除可以异步。文案用“已过期 · 待清理”和“已清理”，替代没有证据的“自动焚毁成功”。所有删除、分享和领取操作都应有幂等键及可查询结果；未知结果不得盲目自动重试非幂等请求。

## 7. 配置与错误处理

连接设置分两步：云存储（复用现有配置）和取件服务（统一次数与网页分享）。普通用户只看到连接状态、检测和引导配置；高级折叠区保留服务地址、部署方式及密钥管理。

检查要覆盖：存储访问权限与前缀、服务可达性、服务协议版本、对象桶绑定及共享密钥匹配。检测使用专门的临时测试对象，完成后清理；不能通过领取真实文件测试可用性。

“保存配置”与“测试连接”分离；密钥空白沿用旧值，清除另设显式动作；切换工作空间或锁定时清空已展示的码、链接、密钥与临时数据。部署过程折叠成授权、准备资源、发布、验证四个阶段，技术日志按需展开；不在主页面展示十二个底层步骤。

错误就地处理：文件太大在待寄存区，码错误在输入框，连接异常在连接栏，分享失败在分享区域，写盘失败在领取结果。一次任务的 loading 不锁住整页。码错误/暴力尝试实施服务端限流，前端显示明确可重试时间；不要只禁用前端按钮。

## 8. 具体例子

| 情况 | 应有结果 |
| --- | --- |
| A：自己寄存报告，24 小时、1 次；选择文件后取消 | 没有开始上传，没有生成码，没有消耗名额 |
| B：上传成功，分享服务超时 | 列表保留该文件，提示分享未完成；点击重试只补分享登记 |
| C：一次领取在解密后保存失败 | 显示本次领取的保存失败，提供原会话恢复/另存；不能简单新建领取，也不能宣称云端文件一定还在 |
| D：文件还有 18 小时、2 次剩余，点击停止分享 | 分享入口停用；本人仍能按剩余规则取回；不删除对象 |
| E：文件到期，存储服务暂时离线 | 新领取被拒绝，显示“已过期 · 待清理”；恢复后清理，确认删除才显示已清理 |
| F：两个设备同时请求最后一次 | 服务端只发放一个名额；另一请求收到“已被占用/无剩余名额”，同一操作的网络重试不再次扣减 |

## 9. 实施顺序与验收门槛（确认后执行）

1. 先补状态与协议：停止分享/删除分离、领取幂等与结果查询、统一计数及清理状态、旧版本兼容。
2. 再接工作台、待寄存表单、分类取件、交接卡与连接引导；避免提前上线错误的成功文案。
3. 覆盖异常：上传超时、登记失败、分享失败、无网络、磁盘写满、入库失败、取消、到期竞态、多设备抢最后一次、服务重启、原会话恢复、清理失败。
4. 桌面 980×620、840×520；移动端 390×844、320×640；浅/深色、键盘与触摸、长文件名、列表为空/多条/失败。普通接收操作不受配置草稿刷新干扰。
5. 使用独立存储前缀与测试服务做真实上传/下载/清理验证，核对原文件哈希、最终保存文件、远端对象、计数及操作状态。仅 UI 模拟通过不能宣称端到端功能验收。

设计交付轮只提供了方案与带示例数据的效果图。效果图的选择、筛选、寄存与取件均为本地演示，不调用产品 IPC、不连接云服务、不读取真实文件。

已确认的选择：采用“管理工作台”，默认自己取用、24 小时、1 次，协议修正与 UI 一起实施。
