# 统一语言与应用内更新计划

> 配套文档：`docs/发布新版本流程.md`、`docs/程序更新功能设计.md`、`docs/移动端App开发计划.md`、`docs/release-download-guide.md`
> 定位：把「每平台一份安装包 + 运行时 i18n + 移动端应用内更新」落成可执行方案。本文只规划，不改业务代码。
> 基线：`dev` · 仓库当前版本 `1.5.1` · 制定日期 2026-09-14
> 纪律：实现只在 `dev`；测试通过后再合 `release` 发版。品牌字符串只改 `scripts/brand.mjs`。标题栏 / 移动端顶栏禁止 `getName()`。

---

## 0. 一句话结论

**桌面发版退出编译期 zh/en 矩阵：每平台只出一份安装包，UI 语言在运行时切换；安装向导 / 系统语言只决定「开始菜单、卸载项显示名」等 OS 外壳，不再决定二进制里有哪种文案。更新永远拉一份 `latest.json`。官方 `tauri-plugin-updater` 不能装 APK，安卓侧载走自研下载 + 系统安装器；iOS 只走商店。**

第一期必须先做运行时 i18n（工作流 B），再把统一包推上正式 Release（工作流 A）。否则「一份安装包」仍然只有一种界面语言，问题只是从 60+ 附件缩成「选错语言就没得换」。

## 1. 背景与现状

### 1.1 为什么 Release 有 60+ 附件

当前 `.github/workflows/release.yml` 是 **3 平台 × 中英 = 6 路桌面**，外加 **2 路安卓**：

| 矩阵 | 每路典型产物 |
|---|---|
| Windows × zh/en | NSIS `.exe` + `.sig`，MSI + `.sig` |
| macOS Universal × zh/en | `.dmg`，更新用 `.app.tar.gz` + `.sig` |
| Linux × zh/en | `.AppImage` + `.sig`，`.deb` + `.sig`，`.rpm` + `.sig` |
| Android × zh/en | `Git.Keymaster_*_arm64-v8a_{zh-CN\|en-US}.apk` |
| 清单 | `latest-zh-CN.json`、`latest-en-US.json`、兼容旧客户端的 `latest.json` |

再叠加：`tauri-action` 先上传未加语言后缀的文件名，`rename-release-assets.mjs` / `sync-release-assets.mjs` 再改名、补传、删旧名。草稿页上常同时看到「未改名 + 已改名 + 签名 + 三份 JSON」，用户观感就是 60+ 个附件、同一平台还要猜 `zh-CN` / `en-US`。

`docs/release-download-guide.md` 现在也按「成对语言」写下载建议，进一步放大选择成本。

### 1.2 为什么中文自动更新会下到英文包

根因不是 updater 插件坏了，而是 **一份 `platforms.windows-x86_64` 槽位被两路语言任务抢写**：

1. 每个桌面 job 调 `prepare-lang.mjs zh|en`，把 `productName`、窗口 title、`Info.plist`、Android `strings.xml`、`app/.env.production` 的 `VITE_APP_LANG`、以及 `app/src-tauri/gam-lang.txt` 写成该语言。
2. `build.rs` 把 `gam-lang.txt` 打成编译期 `GAM_APP_LANG`。
3. `app/src-tauri/src/update/source.rs` 的 `updater_manifest_name()` 按 `GAM_APP_LANG` 拉 `latest-zh-CN.json` 或 `latest-en-US.json`。
4. 历史事故：中英都写同一个 `latest.json` 的同一平台 URL，后结束的英文 job 把中文 URL 盖成 `*_en-US-setup.exe`。中文安装版（`GAM_APP_LANG=zh` 却误指向被盖掉的 `latest.json`，或旧客户端只认 `latest.json`）就会装上英文包。

已经做的止血（必须保留其意图，不能倒回）：

- 清单按语言拆开，`sync-release-assets.mjs` 用 `mergeLatestJson` 按 locale 合并。
- 全部桌面 job 结束后 `pin-updater-json` 把兼容 `latest.json` **钉成中文清单副本**。
- `scripts/check-release-invariants.mjs` 现在**强制**存在 `latest-zh-CN.json` / `latest-en-US.json` / `GAM_APP_LANG` / `--pin-legacy`。工作流 A 改清单策略时，必须同步改这份护栏，否则 CI 会把正确方案判成失败。

### 1.3 为什么卸载列表会并排两个程序

`installer.nsi` 曾经让 `UNINSTKEY` 跟 `PRODUCTNAME`（御钥师 / Git Keymaster）走。中文包更新成英文包（或反过来）会再写一套卸载键，开始菜单里并排出两个程序。

当前修复（新方案不得破坏）：

- `scripts/brand.mjs`：`WIN_UNINSTALL_ID = WIN_INSTALL_DIR = "GitKeymaster"`。
- `installer.nsi`：`INSTALLIDENTITY` / `UNINSTKEY` / 安装目录固定 ASCII `GitKeymaster`；`DisplayName` 仍写 `${PRODUCTNAME}`。
- 安装时删除 `LEGACY_UNINSTKEY_ZH` / `LEGACY_UNINSTKEY_EN`，并清掉另一种语言留下的快捷方式（`RemoveCrossLanguageShortcuts`）。

统一包之后，**禁止再按 UI 语言或显示名生成第二套卸载键**。显示名可以随安装向导语言变，身份不能变。

### 1.4 前端与移动端现状（与本计划直接相关）

| 点 | 现状 |
|---|---|
| i18n 库 / `locales/` | **没有**。菜单、设置、向导、Toast 全部中文写死 |
| 编译期语言 | `vite.config.ts` 用 `VITE_APP_LANG` → `APP_LANG` / `APP_NAME`；左上角只渲染编译期 `APP_NAME` |
| 桌面导航 | `app/src/ui/Layout.tsx`：`身份总览` / `密钥管理` / `SSH 配置` / … |
| 移动端导航 | `app/src/ui/MobileShell.tsx`：`总览` / `2FA` / `账密` / `同步` / `设置` |
| 设置 | `Settings.shared.tsx` / `Settings.mobile.tsx` / `Settings.desktop.tsx`，无语言项 |
| 移动端设置头图 | `Settings.mobile.tsx` 写死 `御钥师 · Git Keymaster`（中文用户可见英文品牌，第一期必须改掉） |
| 向导 | `Init.shared.tsx` / `Init.mobile.tsx`、`useInitModel.ts` 步骤名全中文 |
| 本机配置 | `AppConfig`（`app_config.rs`）无 `uiLocale` 字段 |
| 桌面更新 | `tauri-plugin-updater` 仅桌面三 OS；`lib.rs` 用 `cfg(not(android/ios))` 注册 |
| 移动端更新 | `platform::self_update_supported()` 在 `cfg(mobile)` 为 `false`；`check_update` / `download_and_install_update` 直接 `Unsupported`；`Cargo.toml` 不把 updater 拉进 Android/iOS |
| 移动端设置「关于与更新」 | 仍渲染 `AboutUpdateCard`，但 `selfUpdateSupported === false`，只能「手动下载」 |

## 2. 目标架构

### 2.1 两条语言轨道（必须分开，再在产品上对齐）

```
                    ┌─ 安装期语言（installer locale）
一份安装包 ─────────┤     NSIS 向导 / 系统 UI 语言 / macOS lproj / Android values-xx
                    │     只写：ARP DisplayName、开始菜单、程序坞短名、桌面快捷方式
                    │     身份永远是 GitKeymaster / git-keymaster / com.jeck.gitkeymaster
                    │
                    └─ 运行时 UI 语言（uiLocale）
                          存在 %APPDATA%\git-keymaster\config.json（及移动端沙箱同等文件）
                          决定：菜单、设置、向导、Toast、标题栏品牌字
                          默认：跟系统走；可在设置里改；不新建卸载项
```

**统一规则：**

1. 安装包语言选择 ≠ 运行时 UI 语言。前者写 OS 外壳，后者画 React 树。
2. 首次启动：`uiLocale` 缺省时读系统语言（`zh*` → `zh`，否则 `en`）；若安装器曾写入 `Installer Language` / 同目录 hint，可作为更准的初值，但仍写入 `config.json` 的 `uiLocale`，之后只认这份配置。
3. 应用内改语言：**只改 `uiLocale` + 重渲染**。不改 `UNINSTKEY`，不改安装目录，不改 `productName` 二进制元数据，不调用 `getName()`。
4. 静默自动更新（NSIS `/UPDATE`）：复用已写入 `MANUPRODUCTKEY` 的 `Installer Language`（`installer.nsi` 已有 `MUI_LANGDLL_REGISTRY_*`），按该语言重写 `DisplayName` / 快捷方式，**仍写同一 `UNINSTKEY`**。这样不会再并排两个程序，也不会因为更新把「御钥师」改回英文（或反过来），除非用户重新跑安装向导并改了安装语言。

### 2.2 显示名何时变成「御钥师」

来源永远是 `scripts/brand.mjs` 的 `ZH_DISPLAY_NAME` / `EN_DISPLAY_NAME`，禁止前端或 NSIS 再抄一份字面量。

| 表面 | 何时变成「御钥师」 | 应用内切到英文后还变吗 |
|---|---|---|
| 标题栏、移动端顶栏、设置里的应用名 | 运行时 `displayNameFor(uiLocale)`，`zh` 即为「御钥师」 | **立刻变**（重渲染，不重启） |
| Windows 开始菜单 / 控制面板卸载名 | 安装向导选简体中文，或系统语言为中文且用户未改向导 | **不变**（避免第二套卸载项）。下次**交互安装**才按新的安装期语言改 `DisplayName` |
| macOS 程序坞 / 菜单栏短名 | 系统语言为中文时读 `zh_CN.lproj/InfoPlist.strings` | **不变**（改 Info.plist 缓存不可靠）。跟系统语言，不跟应用内开关 |
| Android 启动器名 | `res/values/strings.xml` 默认「御钥师」；`values-en` 为 Git Keymaster，跟系统 locale | 第一期跟系统，不跟应用内开关（避免和桌面「不改 OS 外壳」不一致） |
| Linux `.desktop` `Name[zh_CN]` | 系统桌面环境 locale | 同上 |
| 安装目录、主程序、包文件名 | 永远 `GitKeymaster` / `git-keymaster` / `Git.Keymaster_*` | 永不随语言变 |

仓库默认 `tauri.conf.json` 的 `productName` / 窗口 `title`、`Info.plist` 默认值保持「御钥师」（中文包不变量）。统一包不再在 CI 里把它们改成 Git Keymaster。

### 2.3 一份安装包如何选出语言

**Windows NSIS（主路径）：**

- `tauri.conf.json` → `bundle.windows.nsis.languages: ["SimpChinese", "English"]`，`displayLanguageSelector: true`。
- `installer.nsi` 已有 `MUI_LANGDLL_DISPLAY` 与语言注册表。补一块：**按 `$LANGUAGE` 选择显示名**，例如简体中文 → 御钥师，否则 Git Keymaster；`WriteRegStr ... DisplayName` 与开始菜单快捷方式用这个变量，不用编译期死掉的 `${PRODUCTNAME}` 当唯一来源。
- `${PRODUCTNAME}` 可继续作为中文回退（与仓库默认一致），但 **UNINSTKEY 继续用 `INSTALLIDENTITY`**。
- 被动/更新模式（`/P` `/UPDATE`）不弹语言框，读注册表里上次的 `Installer Language`。

**Windows MSI：**

- 第一期仍出一份 MSI（格式不是语言）。WiX 多语言变换成本高，**MSI 向导不做中英选择**；安装 UI 跟仓库默认中文。应用打开后仍按 `uiLocale` / 系统语言。下载建议写清：要向导选语言请用 NSIS。

**macOS：**

- 一份 Universal `.dmg`。提交 `zh_CN.lproj` / `en.lproj` 的 `InfoPlist.strings`（`CFBundleName` / `CFBundleDisplayName`），不要再靠 `prepare-lang.mjs` 把同一份 `Info.plist` 改成英文再打第二包。

**Linux：**

- 一份 AppImage / deb / rpm。`.desktop` 写 `Name=Git Keymaster` + `Name[zh_CN]=御钥师`（Name 的英文是给非中文桌面；中文用户可见的是 `Name[zh_CN]`）。

**Android：**

- 一份 `arm64-v8a` APK。`values/strings.xml` = 御钥师，`values-en/strings.xml` = Git Keymaster。`prepare-lang.mjs` **停止**在 CI 里覆盖 `app_name` 为单一语言。
- 商店（若以后上 Play）与侧载都用这一份；不要再打 zh/en 两个 APK。

**文件名（不再带 locale）：**

- `Git.Keymaster_{version}_x64-setup.exe`
- `Git.Keymaster_{version}_universal.dmg` / `.app.tar.gz`
- `Git.Keymaster_{version}_amd64.AppImage`
- `Git.Keymaster_{version}_arm64-v8a.apk`

### 2.4 更新清单：一份 `latest.json`

```
https://github.com/ice-juice/git-keymaster-app/releases/latest/download/latest.json
```

- 桌面 `platforms` 仍是 `windows-x86_64` / `darwin-*` / `linux-x86_64`，URL 指向**无语言后缀**的安装包。
- 工作流 A 落地后：`updater_manifest_name()` 固定返回 `latest.json`；删除对 `GAM_APP_LANG` 的依赖。
- `tauri.conf.json` `plugins.updater.endpoints` 改为上述 `latest.json`。
- **旧客户端兼容（至少跨 2 个正式版）：** 发版结束时把同一份内容再上传为 `latest-zh-CN.json` 与 `latest-en-US.json`。旧中文包、旧英文包都会更新到**同一份统一包**（这正是想要的）。`pin-legacy` 从「钉成中文清单」改为「三份文件字节级相同」。
- 安卓条目：`android-aarch64` 写入同一份 `latest.json`（给工作流 C 用）。官方桌面 updater 不认识它，会忽略；不会让 Windows 去下 APK。

### 2.5 编译期 zh/en 矩阵如何退出

| 旧物 | 新职责 |
|---|---|
| `release.yml` `matrix.lang: zh\|en` | 桌面每平台 1 job；安卓 1 job |
| `prepare-lang.mjs zh\|en` | 改为 `prepare-lang.mjs unified`（或删矩阵调用）：打开 NSIS 双语 + 选择器；保证 Android `values`/`values-en`、macOS lproj 存在；**禁止**写 `app/.env`；**禁止**再写用于拆清单的 `gam-lang.txt` |
| `rename-release-assets.mjs` 盖 `_{zh-CN\|en-US}` | 只做 ASCII 主干规范化（`御钥师_` → `Git.Keymaster_`），不再盖 locale |
| `sync-release-assets.mjs` 按 locale 合并 | 按**平台**合并进唯一 `latest.json`；最后复制两份旧名别名 |
| `check-release-invariants.mjs` | 改断言：单一 `latest.json`、NSIS 含两种语言、UNINSTKEY 仍是 `GitKeymaster`、TitleBar 无 `getName()`、存在 `values-en`；删掉「必须 GAM_APP_LANG + 拆清单」 |

本地 `tauri dev`：不再需要 `VITE_APP_LANG` 决定整棵 UI。缺省跟系统或 `zh`。`prepare-lang` 继续不得写 `app/.env`。

## 3. 三个工作流：范围、顺序、并行

```
工作流 B  前端 i18n + 应用内切语言     ← 统一包能「换语言」的前提
    │
    │  脚本/CI 骨架可并行，但第一份正式统一包必须含 B
    ▼
工作流 A  发版瘦身（一份包 + 一份 latest.json）
    │
    │  清单格式（含 android-aarch64）与 A 对齐后接入
    ▼
工作流 C  安卓侧载应用内更新（iOS 只预留商店入口）
```

| 工作流 | 范围 | 依赖 | 可并行 |
|---|---|---|---|
| **A 发版瘦身** | CI 矩阵、改名/同步脚本、NSIS 双语与 DisplayName、不变量、发版文档、旧清单别名 | **正式发统一包前必须已合入 B**（否则包里只有中文 UI） | 与 B **同时改脚本/护栏**；不要先 Publish |
| **B 前端 i18n** | 文案目录、Provider、设置项、标题栏品牌、Init/Unlock/导航；`AppConfig.uiLocale` | 不依赖 A 出包 | 与 A 的脚本工作并行 |
| **C 移动端更新** | 安卓下载 APK + 系统安装器；`latest.json` 的 `android-aarch64`；设置页按钮；iOS 文案 | 依赖 A 的清单约定；复用 B 的设置文案 key | 设计/原生安装器可与 A 后半并行；合入前 A 的 JSON 形状要冻住 |

建议工期（1 人串行约 2.5–3.5 周；A+B 两人可压到约 2 周）：B 约 8–12 工作日 → A 约 4–6 工作日（含一次草稿 Release 抽检）→ C 约 5–8 工作日（含真机）。

## 4. 工作流 A · 发版瘦身

### 4.1 关键文件

| 文件 | 做什么 |
|---|---|
| `.github/workflows/release.yml` | 桌面矩阵去掉 `lang`；安卓去掉 `lang`；不再 `prepare-lang.mjs zh\|en`；同步脚本不再带 locale 参数；`pin-updater-json` 改为三份 JSON 相同 |
| `scripts/prepare-lang.mjs` | `unified`：NSIS 双语 + 选择器；检查 lproj / `values-en`；不写 `VITE_APP_LANG=en`、不写拆清单用 `gam-lang.txt` |
| `scripts/rename-release-assets.mjs` | 去 locale 后缀；自测用例改成无 `_zh-CN` |
| `scripts/sync-release-assets.mjs` | 单清单合并；`--pin-legacy` 复制为 `latest-zh-CN.json` / `latest-en-US.json` |
| `scripts/check-release-invariants.mjs` | 按 §2.5 改断言；`--prepared unified` |
| `scripts/brand.mjs` | 只当显示名/身份源，**不**为统一包新增第三品牌 |
| `app/src-tauri/windows/installer.nsi` | `$LANGUAGE` → 显示名；`DisplayName`/快捷方式用变量；`UNINSTKEY` 不动 |
| `app/src-tauri/src/update/source.rs` | `updater_manifest_name()` → `latest.json`；单测改 URL |
| `app/src-tauri/build.rs` | 停止注入 `GAM_APP_LANG`（或固定无意义占位并禁止再被 source.rs 读取） |
| `app/src-tauri/tauri.conf.json` | `endpoints` → `latest.json`；nsis `languages` + `displayLanguageSelector` |
| `app/src-tauri/Info.plist` + 新增 lproj | 默认中文；英文进 `en.lproj` |
| `app/src-tauri/gen/android/.../res/values-en/strings.xml` | 新增 |
| `docs/发布新版本流程.md`、`docs/程序更新功能设计.md`、`docs/release-download-guide.md` | 改为「每平台一份」；成功标准从「8 路出包」改为「3 桌面 + 1 安卓」 |

### 4.2 验收标准

- 打 `v*` 后草稿附件大约：**Windows 4**（exe/msi + 两个 sig）+ **macOS 3–4** + **Linux 6** + **APK 1** + **JSON 3（内容相同）** ≈ 18，不再出现成对 `zh-CN`/`en-US` 安装包。
- `latest.json` 的 `windows-x86_64.url` 不含 `_en-US` / `_zh-CN`；连续两个 job 写入不得互相覆盖语言包（因为已经没有第二种包）。
- 中文旧版（读 `latest-zh-CN.json`）与英文旧版（读 `latest-en-US.json`）都能升到统一包。
- 中文系统上 NSIS 默认/向导选中文后，开始菜单与 ARP 为「御钥师」，卸载项只有 **一个** `GitKeymaster`。
- 该机再装「同一份」安装包并在向导改选 English：仍是同一卸载项，DisplayName 变为 Git Keymaster，**不会**并排两个程序。
- `node scripts/check-release-invariants.mjs --test` 绿。
- 中文用户可见表面没有写死的 `Git Keymaster`（安装目录/文件名除外）。

### 4.3 风险

| 风险 | 等级 | 对策 |
|---|---|---|
| 先发统一包、B 未合入 | 高 | 发版手册写死：A 的 tag 必须含 B |
| 不变量脚本仍要求拆清单，CI 红或反过来放行旧矩阵 | 高 | A 与 invariants **同一 PR** |
| NSIS `$LANGUAGE` 与快捷方式名不同步，更新后又并排 | 高 | 快捷方式创建/清理一律用「当前安装期显示名」+ 已有 `RemoveCrossLanguageShortcuts` / legacy key 删除 |
| 旧英文客户端升上来后开始菜单仍是 Git Keymaster，用户以为没统一 | 低 | 预期行为；UI 已可切换。文档写明 |

## 6. 工作流 C · 移动端应用内更新

### 6.1 官方 updater 在 APK 上不可行

`tauri-plugin-updater` 只编进 Windows / macOS / Linux（`Cargo.toml` target 依赖）。它会静默跑 NSIS、替换 `.app`、替换 AppImage，**没有 Android PackageInstaller / iOS 换包实现**。

即便把 APK URL 写进 `latest.json`，插件既不会认 `android-aarch64` 为可安装目标，也不能在已运行的 WebView 进程里覆盖 `/data/app`。`lib.rs` 用 `target_os` 排除插件是对的，**不要为了 C 把官方 updater 编进 APK**。

### 6.2 替代路径（第一期：侧载）

```
设置 / 启动检查
  → 复用 update/source.rs 解析同一份 latest.json（移动端也要能 check）
  → 读 platforms["android-aarch64"]
  → reqwest 下载到应用缓存（走已有代理配置）
  → 校验：当前安装签名证书 == APK 签名（PackageManager）；可选再校 minisign（若 CI 给 APK 配 .sig）
  → FileProvider + ACTION_INSTALL_PACKAGE / PackageInstaller
  → 用户点系统安装确认（Android 8+ 还要「安装未知应用」）
  → 覆盖安装（同一 applicationId + 同一 upload keystore）
```

| 文件 | 做什么 |
|---|---|
| `app/src-tauri/src/platform/mod.rs` | 拆语义：`store_update_supported`（永远 false，直到上 Play）/ `sideload_update_supported`（Android true，iOS false）/ 桌面仍用现有 `self_update_supported` |
| `app/src-tauri/src/commands/update.rs` | 移动端 `check_update` 不再直接 `Unsupported`；Android `download_and_install_update` 走侧载安装器 |
| `app/src-tauri/src/mobile/update.rs`（新建） | 下载、校验、唤起安装器；Kotlin 胶水可放 `gen/android` 或独立 plugin |
| `app/src-tauri/gen/android/.../AndroidManifest.xml` | `REQUEST_INSTALL_PACKAGES`（仅侧载渠道） |
| `release.yml` + `sync-release-assets.mjs` | 上传 APK 时合并 `android-aarch64` 进 `latest.json` |
| `AboutUpdateCard` / `Settings.mobile.tsx` | Android：检查 + 下载并安装；文案不再写「请到应用商店」作为唯一出路 |
| iOS | `self_update_supported = false`；按钮改为「在 App Store 中打开」（M13 有账号后再填 URL）。**禁止**做 IPA 侧载更新 |

**商店策略（单独写，不与侧载混用）：**

| 渠道 | 第一期 | 以后 |
|---|---|---|
| GitHub 侧载 APK（现状） | 自研下载 + 系统安装器 | 保持 |
| Google Play（P3 未定） | 不做 | Play In-App Updates；检测到安装来源为 `com.android.vending` 时**关掉**侧载安装器，避免两套更新打架 |
| iOS App Store / TestFlight | 不做实现，只留入口文案 | M13 + Apple 账号后接 `itms-apps://` |

keystore 丢失则无法覆盖安装——继续遵守 `docs/移动端App开发计划.md` 的 P4（两份离线备份）。不要为更新换一把新钥匙。

### 6.3 验收标准

- 真机装旧正式 APK（同一 keystore），检查到新版本，下载后系统安装框能覆盖，打开后版本号正确。
- 签名不一致的 APK 被拒绝，并提示「不是同一发布者，请卸载重装」（不自动卸载）。
- 桌面三端更新回归：仍走官方插件 + minisign，行为不变。
- iOS 构建（若有）看不到「下载 APK」。
- 无网 / 用户拒绝未知来源：有明确错误，应用不崩。

### 6.4 风险

| 风险 | 等级 | 对策 |
|---|---|---|
| 官方插件硬编进 Android | 高 | 保持 Cargo target 排除；C 自写模块 |
| 换 keystore | 高 | 文档 + CI 仍用现有 Secrets |
| `REQUEST_INSTALL_PACKAGES` 上架被拒 | 中 | 上 Play 时走商店 API 并去掉该权限；侧载包可保留 |
| 后台下载被杀 | 中 | 只在前台下；进度条；失败可续或重下整包 |
| 把桌面 `download_and_install` 误接到 APK URL | 中 | 平台键与安装器分支用 `cfg` / `updater_target()` 锁死 |

## 7. 切换语言要不要重启

**结论：切换运行时 UI 语言不需要重启 App。**

| 层 | 要不要重启 | 理由 |
|---|---|---|
| 已渲染 React 文案 | 否 | i18n 换 locale 后组件重绘 |
| 标题栏 / 移动端顶栏品牌 | 否 | 不再用编译期死 `APP_NAME`，也不读 `getName()`；用 `displayNameFor(uiLocale)` |
| `GAM_APP_LANG` | 不适用 | 统一包后删除；更新与 UI 语言脱钩，只拉 `latest.json` |
| NSIS / 开始菜单 / ARP 显示名 | **不是重启能改的** | 那是安装期写进注册表的外壳。应用内切换若去改 `UNINSTKEY` 或另写一套卸载项，会复发「并排两个程序」。留给下次交互安装 |
| macOS 程序坞短名 | 否（也改不了） | 跟 `*.lproj` + 系统语言，跟应用内开关无关 |
| Android 启动器名 | 否 | 第一期跟系统 `values` / `values-en` |
| 少数 Rust 中文错误 | 否 | 第一期不做后端 i18n；不因此强迫重启 |

设置里切「跟随系统」：写回 `system` 并按**当前** OS 语言立刻重绘；OS 以后再变，等下次冷启动读取即可。第一期不监听系统语言广播。

## 8. 建议的子 agent 分工

实现阶段（不是本文）建议 3 个 agent，都在 `dev` 上开，禁止直接改 `release`。

### Agent 1 · 发版矩阵与清单（工作流 A）

- **输入：** 本文 §2、§4；`release.yml`；`scripts/{brand,prepare-lang,rename-release-assets,sync-release-assets,check-release-invariants}.mjs`；`installer.nsi`；`update/source.rs`；三份发版文档。
- **禁止改：** `app/src/pages/**` 业务文案、保险库/同步/生物识别、`TitleBar` 去调 `getName()`、把 `UNINSTKEY` 改回 `${PRODUCTNAME}`。
- **完成定义：** 本地 `node scripts/check-release-invariants.mjs --test` 绿；工作流矩阵为 3+1；文档与下载建议不再要求用户挑 zh/en 包；`source.rs` 单测指向 `latest.json`。不打正式 tag。

### Agent 2 · 运行时 i18n（工作流 B）

- **输入：** 本文 §2、§5、§7；`brand.mjs`；`config.ts` / `vite.config.ts`；`Layout` / `MobileShell` / `TitleBar`；`Settings*` / `Init*` / `Unlock*`；`app_config.rs`。
- **禁止改：** `release.yml` 矩阵、`installer.nsi` 的 `INSTALLIDENTITY`/`UNINSTKEY`、更新 endpoints、用 `getName()` 或运行时 `productName` 当标题。
- **完成定义：** 设置可切语言且不重启；中英文导航/设置/向导可用；中文模式无写死 Git Keymaster；`config.json` 能记住 `uiLocale`；TitleBar 仍只渲染品牌变量。

### Agent 3 · 安卓侧载更新（工作流 C）

- **输入：** 本文 §6；`commands/update.rs`；`platform/mod.rs`；`update/mod.rs`；`AboutUpdateCard`；`release.yml` 安卓上传段。
- **禁止改：** 桌面 minisign / `tauri-plugin-updater` 注册方式；把官方 updater 加进 Android 依赖；iOS 侧载；发版身份与显示名规则。
- **完成定义：** Android 真机能检查、下载、调起安装器并覆盖（同一 keystore）；桌面 `cargo test` 不回退；iOS 无 APK 入口。

协调：Agent 1 与 2 可并行，但 **Publish 统一包前 1+2 都要合入**。Agent 3 等 `latest.json` 的 `android-aarch64` 字段冻结后再接 CI。

## 10. 回归护栏（防止两类事故再发）

改完 A/B/C 任一工作流，必须仍能被 `check-release-invariants.mjs` 锁死：

1. **不再抢写清单：** 只有一份逻辑清单；旧名只是复制。禁止两个 job 往不同语言 URL 写同一 `platforms.*`。
2. **不再两套卸载项：** `UNINSTKEY` = `GitKeymaster`；安装/更新删除 legacy 中英键；应用内切语言不准写注册表卸载项。
3. **品牌：** 中文用户可见名不是 Git Keymaster；`CFBundleName` 默认「御钥师」+ lproj；标题栏无 `getName()`。
4. **`prepare-lang` 不写 `app/.env`。**

发版手册「中文更新下到英文包」条目改为：「统一包后不应再发生；若发生，先查是否又引入按语言拆的 `latest-*.json` 且 URL 指向不同安装包。」
