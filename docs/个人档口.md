# 个人档口（personal-stall）

> 独立开发者自己部署的软件收费档口：个人身份收款、签发离线激活码、寄到买家邮箱。不必先注册公司。
> 个人档口不是代收款平台。每个开发者用自己的 Cloudflare、支付和发信账号部署一份，钱和授权私钥都在自己名下。
> 御钥师是第一个接入的软件。激活码字节格式、指纹和应用内验签见 [`专业版授权与激活码设计.md`](专业版授权与激活码设计.md)。换一个软件就换一份契约，个人档口只负责签这份契约规定的文本。
> 本文是个人档口的设计稿，实现放在独立仓库，不进御钥师的应用代码。
> 制定日期：2026-09-22
> 状态：**设计稿，待评审后分期实施**。

---

## 第一部分 · 定位

独立开发者要给软件收费，常见的拦路是：信用卡代收要公司主体，钱结到境外账户再换回人民币还要结汇。个人档口绕开这件事，而不是绕开纳税和平台审核。

开发者用个人身份接上三路收款，个人档口在付款被确认之后签名、发信：

| 买家 | 收款 | 自动化程度 |
|---|---|---|
| 海外 | Gate Pay 托管收银台，结算 USDT | 回调验签后自动发码 |
| 国内，愿意用爱发电 | 爱发电订单 webhook | 验签并查单后自动发码 |
| 国内，微信 / 支付宝个人码 | 手机通知转发 | 人工点确认后才发码 |

买家不注册个人档口账号。留下邮箱，收到激活码，粘贴进软件。软件只内置开发者的公钥，离线验签。

个人档口明确不做的事：

- **不代持资金，也不做成给很多人用的收银台 SaaS。** 一份部署服务一个开发者的一个或几个软件。
- **不代替注册公司去开发票。** 要专票的客户仍然买不了。个人收款和爱发电覆盖的是不需要公司抬头的买家。
- **不碰用户的业务数据。** 订单库里只有订单号、邮箱、金额、指纹哈希和许可证副本。
- **不在 NAS 上签名，也不把签名接口用 Cloudflare Tunnel 暴露到家里。** 见 4.4。
- **不注入微信或支付宝，也不接免签约码支付。** 见 6.3。

---

## 第二部分 · 目标

1. 付款成功后自动签名，并用邮件把激活码寄到买家留下的邮箱。
2. 同一订单可免费换到最多 3 台机器。超过则人工处理。
3. 退款后发布吊销名单，软件下次检查更新时生效。
4. 代码和私钥放在开发者自己的私有仓库。软件仓库只编译进公钥。

---

## 第三部分 · 与软件的契约

个人档口不规定许可证里有哪些字段。每个软件交一份规范文本说明，个人档口对那段文本做 Ed25519 裸签名。御钥师的说明在激活码设计文档第四部分和第六部分，要点如下，换软件时整表替换：

| 项 | 御钥师的要求 |
|---|---|
| 载荷 | `git-keymaster-license-v1` 行文本，字段只有 `order` / `to` / `tier` / `issued` / `machine` |
| 签名 | Ed25519，对规范文本的 64 字节裸签名 |
| 激活码 | `base64( 规范文本 + "\n---\n" + base64(签名) )` |
| 机器数 | 一个订单最多 3 个 `machine` 行 |
| 吊销文件 | `git-keymaster-revocation-v1`，用同一把授权私钥签，经 `GET /revocation.txt` 提供 |
| 申请码 | 软件给出 `指纹@版本`。个人档口只把指纹写入 `machine` 行 |

两侧共用同一组测试向量。Worker 导入私钥用 PKCS#8。Cloudflare 不支持以 raw 格式导入 Ed25519 私钥。

订单号前缀区分渠道，软件将其视为不透明字符串：`gp_`（Gate Pay）、`afd_`（爱发电）、`wx_`（个人收款人工确认）。

同一订单追加机器时，新载荷包含全部已绑定指纹。旧码仍只匹配它自己写下的机器。吊销按整个订单号，不在载荷里放签发代数。

## 第四部分 · 部署

### 4.1 平台分工

| 平台 | 角色 |
|---|---|
| Cloudflare Worker | 验 webhook、签名、处理换机与人工确认 |
| Cloudflare D1 | 订单、已绑定指纹、一次性链接 |
| Cloudflare Pages | 购买页、换机页 |
| DNSHE 免费域名 | `pay` 的 CNAME 指向 Worker；Resend 要求的 SPF、DKIM、DMARC |
| Resend | 从 `license@域名` 发激活码。免费档每天 100 封、每月 3000 封 |
| Gmail | Resend 的 Reply-To；半自动确认信和失败告警的收件箱 |
| Gate Pay | 海外收款。托管收银台，结算币种指定为 USDT。见第五部分 |
| 爱发电 | 国内自动收款。见第六部分 |

Vercel 不参与。Hobby 计划不用于收费产品。

DNSHE 不必把整域 NS 切到 Cloudflare。Resend 的 TXT / CNAME 按控制台原样添加，不要对这些记录开橙色代理。新的免费域名容易进垃圾箱，上线前先向自己的 Gmail 发一封测试信。

Workers 免费档足够一个人的软件销量：每天 10 万次请求；D1 每天 500 万行读、10 万行写。一次 Ed25519 签名远低于免费档 10 毫秒 CPU。

密钥全部在 `wrangler secret`：`LICENSE_SK`（授权私钥）、`LINK_HMAC_SECRET`（魔法链接，与授权私钥分开）、`GATEPAY_CLIENT_ID`、Gate 支付 API Secret、爱发电 token、SmsForwarder 共享密钥、`RESEND_API_KEY`。

### 4.2 订单

D1 表 `orders`：

| 列 | 含义 |
|---|---|
| `order_id` | 主键。`gp_` / `afd_` / `wx_` 加渠道单号或购买页短码 |
| `email` | 寄激活码和换机链接的地址 |
| `source` | `gatepay` / `afdian` / `manual` |
| `amount` | 实付金额，供个人收款通知做候选匹配 |
| `fp` | 下单时带上的指纹；当时没有则可空 |
| `machines` | 已写入许可证的指纹，最多 3 个 |
| `status` | `pending` / `paid_unbound` / `fulfilled` / `revoked` |
| `updated_at` | 最近一次状态变化 |

`tokens` 表保存魔法链接和人工确认链接的 `jti`、用途、过期时间、是否已用。用过即作废。

已支付订单的写入使用 `INSERT ... ON CONFLICT DO NOTHING`。冲突直接按该渠道要求返回成功，避免重试时签出第二串码或再发一封信。

### 4.3 接口

| 路径 | 行为 |
|---|---|
| 购买页 `/?fp=` | 收集邮箱。有 `fp` 就写入待支付订单。海外接着创建 Gate 收银台；国内跳爱发电，页面上写明把申请码放进留言 |
| `POST /webhook/gatepay` | 见第五部分。验签失败不得回 SUCCESS |
| `POST /webhook/afdian` | 见 6.1 |
| `POST /reissue/request` | 购买邮箱 + 新申请码。向该邮箱发 30 分钟魔法链接。同一邮箱按天限次 |
| `GET /reissue/confirm` | 未满 3 台则追加指纹、重签、寄新码。该指纹已在列表里则重寄现有码 |
| `POST /notify/payment` | 仅接受 SmsForwarder。**不签名**，见 6.2 |
| `GET /revocation.txt` | 返回已缓存的签名吊销名单，见第七部分 |

绑定链接与换机链接都是 `HMAC(用途 + 订单号 + 指纹 + 过期时间)`，密钥用 `LINK_HMAC_SECRET`。

付款成功且订单里已有指纹：签名并寄出激活码，状态改为 `fulfilled`。当时没有指纹：状态改为 `paid_unbound`，邮件里是绑定链接，用户在电脑上粘贴申请码后再签。

### 4.4 为什么不在 NAS 上签名

付款回调要求签名端随时在线。家里断电、休眠或 Tunnel 断开时，用户付了款收不到邮件。Tunnel 还会把签名接口暴露到家庭网络。

若将来坚持私钥不出家，NAS 应主动向外拉取待签订单，而不是对外开放签名端口。当前单量不采用。软件更新包的签名私钥继续离线保管，不放进个人档口。

### 4.5 应急

Worker 或 Resend 不可用时，私有仓库里的脚本用同一把私钥手工签一串码，从 Gmail 寄出。私钥从密码管理器取出，不进 git。脚本与 Worker 必须生成同一份规范文本。第 4 台机器不自动加，只走这个脚本，由人工决定。

## 第五部分 · 海外收款：Gate Pay

海外不走信用卡代收。那些渠道把钱结到境外银行账户，再换回人民币才是结汇。Gate Pay 托管收银台把营收币种指定为 USDT，到账在开发者自己的 Gate 商户账户。

下单顺序：

1. 购买页提交邮箱和指纹。Worker 先在 D1 插入 `pending` 订单，`merchantTradeNo` 用 `gp_` 加订单号。
2. Worker 调用 `POST /v1/pay/checkout/order`。`currency` 与 `expectCurrency` 为 USDT，金额按当次标价锁定，`returnUrl` 回到购买页。指纹不放进 Gate 的商品字段。
3. 浏览器转到响应里的 `location`。
4. `POST /webhook/gatepay` 用 HMAC-SHA512 验 `X-GatePay-Timestamp`、`X-GatePay-Nonce`、`X-GatePay-Signature`。只在 `bizType=PAY` 且 `bizStatus=PAY_SUCCESS` 时，再查订单接口核对 `merchantTradeNo` 与金额，通过才签名。
5. 处理成功回应 `{"returnCode":"SUCCESS","returnMessage":""}`。回调没到时用查询接口补偿。

v1 只用托管收银台。不用静态链上地址：一址多笔对不上订单。

标价若展示人民币，在创建这笔预付单时换成 USDT 并锁死，付款过程中的汇率波动不改价。`PAY_REFUND` 把该订单标为 `revoked` 并刷新吊销名单。

这条路径省掉的是「美元进境外卡、再结汇成人民币」。收到的是 USDT。以后若要换成人民币进国内账户，结汇和纳税仍要单独处理。Gate 商户入驻要完成对方的个人身份审核，不要求先有公司。买家需要有 Gate 账户或能付 USDT。

文档：<https://docs.gate.com/api-reference/version/100/cn/endpoint/checkout/order>，通知说明见 Gate Pay 的「通知概览」。

## 第六部分 · 国内收款

国内自动路径是爱发电。个人微信 / 支付宝没有可靠的付款回调，个人码用于经营也有被限制收款的风险。

### 6.1 爱发电（自动）

创作者后台把 webhook 配到 `POST /webhook/afdian`。Worker 先验平台签名，再按订单号调用查询接口核对金额与状态，通过才签名。买家在留言里写申请码；购买页在跳转说明里写清这件事。留言里没有合法申请码时，订单进入 `paid_unbound`，走绑定链接。

验签和查询可参考 `willin/afdian-sdk`、`yiyungent/Afdian.Sdk`，签发放在个人档口的 Worker 里。字段以爱发电开发者说明为准：<https://guide.afdian.com/creator/developer>。

### 6.2 个人收款（半自动）

监听端只用 [pppscn/SmsForwarder](https://github.com/pppscn/smsforwarder)。它读取本机通知栏里已经弹出的微信（`com.tencent.mm`）和支付宝（`com.eg.android.AlipayGphone`）通知，POST 到 `POST /notify/payment`，请求带只有这台手机知道的密钥。

Worker 的处理：

1. 密钥不对直接拒绝。
2. 从通知正文取出金额，在时间窗内查找金额相同、状态为 `pending` 的订单。
3. 恰好一笔时，给 Gmail 发「疑似到账，点此签发」。多笔或零笔只记录，不猜测。
4. 人工点开确认链接之后才签名，才让 Resend 寄给买家。

通知正文通常只有金额和付款人昵称，不能当作结算凭证。这条路径永远不自动签名。手机必须亮着通知、显示内容详情并关闭电池优化。

### 6.3 明确不采用

注入微信或支付宝进程的项目，以及把个人码包装成商户接口的免签约码支付，都不接入。前者导致封号，后者与个人码商用、跑分是同一类做法。

## 第七部分 · 吊销名单的发布

软件消费的文本格式见该软件自己的契约。御钥师的格式在激活码设计文档第六部分。发布侧的规则对所有接入软件相同：

- 订单变为 `revoked` 时重新生成全文并用 `LICENSE_SK` 签名，结果缓存在 Worker 或 KV。
- `GET /revocation.txt` 只返回缓存。不要在每次 GET 时现签，以免被刷 CPU。
- 文件里只有订单号和 `issued` 时间，不含邮箱。
- 退款事件（Gate 的 `PAY_REFUND`、爱发电侧对应的退款状态、人工吊销）是进入 `revoked` 的入口。

## 第八部分 · 买家看到的流程

1. 在软件里点购买，浏览器打开 `https://pay.域名/?fp=指纹`。没有带指纹时，购买页让用户粘贴申请码。
2. 留下邮箱。海外进入 Gate Pay 收银台，国内进入爱发电。
3. 付款成功且当时有指纹：邮件就是激活码。当时没有指纹：邮件是绑定链接。
4. 回到软件，把激活码粘进购买入口。御钥师的入口是「设置 → 专业版」。

换机：新机器打开 `https://pay.域名/machines`，填写购买邮箱和新申请码，点邮件里的链接。同一订单最多 3 台。重装系统若没换主板，旧码通常仍有效，不必重发。换机免费；这条路径不顺，差评会吃掉利润。

## 第九部分 · 分期与风险

| 阶段 | 内容 | 产出 |
|---|---|---|
| P1 | 独立仓库：Worker + D1 + Pages + Resend，应急脚本可签出御钥师契约里的码 | 手工把码寄出也能用 |
| P2 | Gate Pay 收银台 + `revocation.txt` | 海外 USDT 付款自动发码 |
| P3 | 爱发电 webhook | 国内付款自动发码 |
| P4 | SmsForwarder + Gmail 人工确认 | 个人码半自动 |

御钥师应用侧的 M1、M2 可以和 P1 并行。P2 之前用应急脚本卖。

### 已定

- 项目名是个人档口，英文标识 `personal-stall`，独立仓库实现。
- 一份部署属于一个开发者，不做成代收款平台。
- 授权签名在 Workers 上完成，不走 NAS / Tunnel。
- 海外走 Gate Pay 托管收银台，结算 USDT。
- 国内自动走爱发电；个人码只做 SmsForwarder + 人工确认。
- 一单最多 3 台，换机免费重签。

### 风险

1. **授权私钥在 Cloudflare 账号下。** 账号被盗的损失是一批白拿的授权，不是用户的业务数据。软件更新包的私钥不放在同一处。
2. **免费域名的信件进垃圾箱。** SPF、DKIM、DMARC 缺一项，自动发码就等于没发。
3. **Resend 免费档每天 100 封。** 激活码、绑定链接和换机链接共用额度，所以换机接口要限次。
4. **个人收款通知可以伪造进 webhook。** 因此 6.2 必须人工确认，且端点要有共享密钥。
5. **USDT 不是人民币。** 省掉的是境外卡结汇。换成人民币进国内账户时，结汇和纳税仍在。
6. **免注册公司覆盖不了要发票的买家。** 专票仍要经营主体。个人档口只服务不需要公司抬头的购买。

### 待定

- 标价。御钥师的参考坐标是思源买断 80 元（原价标 96）。展示货币与锁汇时点在 P2 实现时定死。
- 一个部署里放几个软件。v1 按御钥师这一份契约做，第二份软件接入时再把载荷模板做成配置。
- 团购码。3 台机器已覆盖个人的第二台电脑，团购不是 v1 的前提。
