## Android 开发

先在项目根目录加载当前终端所需环境，再运行 Tauri：

```powershell
cd E:\juiceProgram\gitKeyMaster
. .\scripts\dev-env.ps1
cd app
npm run tauri -- android build --debug --apk --target aarch64 --ci
```

`dev-env.ps1` 只在当前 PowerShell 进程切换到 JDK 17，不修改其他项目使用的 Java。原有 `scripts/android-device-debug.ps1` 也会加载此环境脚本。Cargo 缓存与项目位于不同盘符时，脚本会通过当前进程的 Gradle 项目属性关闭 Kotlin 增量编译，避免 Kotlin 1.9 的 `this and base files have different roots` 错误；Gradle 任务缓存和 Rust 增量编译仍然保留。Android Studio 和模拟器不是命令行/真机开发的必装项，本次未安装。

**仍需手动开启 Windows 开发者模式**：Windows 设置 → 系统 → 开发者选项（部分系统在“隐私和安全性 → 开发者选项”）→ 开发人员模式。本次管理员确认被取消，因此没有改变此系统设置。Tauri 默认使用符号链接放置 Android 原生库；未开启时普通用户运行上述命令会在符号链接步骤报权限错误，即使 Rust 原生库已经编译成功。

不启用开发者模式时，也可使用本次验证过的“复制原生库 + Gradle”流程。前提是上述 Tauri 命令的**当前这次 Rust 编译已经成功，仅符号链接步骤失败**，不要拿旧 `.so` 掩盖其他编译错误：

```powershell
cd E:\juiceProgram\gitKeyMaster
. .\scripts\dev-env.ps1
$nativeDest = '.\app\src-tauri\gen\android\app\src\main\jniLibs\arm64-v8a'
New-Item -ItemType Directory -Force -Path $nativeDest | Out-Null
Copy-Item .\app\src-tauri\target\aarch64-linux-android\debug\libapp_lib.so $nativeDest -Force
& "$env:NDK_HOME\toolchains\llvm\prebuilt\windows-x86_64\bin\llvm-strip.exe" --strip-unneeded "$nativeDest\libapp_lib.so"
cd app\src-tauri\gen\android
.\gradlew.bat --no-daemon :app:assembleArm64Debug -x rustBuildArm64Debug
```

`-x rustBuildArm64Debug` 让 Gradle 使用刚复制的原生库，避免重新走符号链接步骤。APK 位于 `app/src-tauri/gen/android/app/build/outputs/apk/arm64/debug/app-arm64-debug.apk`，为开发调试签名包。

真机连接及安装见 [安卓真机调试](安卓真机调试.md)。没有连接或操作手机，也没有验证相机、指纹等设备功能。
