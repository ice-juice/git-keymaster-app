# 安全修复：升级与恢复指南

本轮修复代码尚未替你部署云服务、安装桌面/手机应用或修改真实保险库。详细测试状态见[进度](进度.md)。

## 升级兼容性

1. **先做完整离线备份并演练恢复，再升级所有同步设备。** 新版清单将恢复头部与数据版本绑定为一个提交，旧客户端不理解此格式会拒绝解密。不要让旧客户端继续向同一同步位置写入；首次推送先拉取建立版本基线。服务必须正确支持 ETag/If-Match/If-None-Match。
2. **更新清单现在必须签名。** 官方源也不再接受无签兼容路径。发布方需用既有签名流程生成 manifestSignature；不可通过放开验证来修复缺签发布。
3. **Apple 生物识别需重新启用。** 旧文件 KEK/普通钥匙串绑定不再被当作安全凭据。先确认访问密码或恢复码可用，新系统绑定失败不回退到文件存密钥。最低 macOS 10.15，实机正式签名/entitlement 验收另列。
4. **寄存分享旧链接需要重新复制。** 新链接包含认证的文件长度及上下文，拒绝旧未认证链接。服务器和客户端均应升级到兼容的 V2，停止分享只撤销入口；取件失败保留原操作 ID，在恢复窗口内继续，不新建另一笔取件。
5. **锁定期间暂停解密同步。** 锁定会撤销共享主密钥会话。ssh-agent 是独立的签名服务，2026-11-16 已取消强制 15 分钟期限，避免开发过程中反复解锁。已加载的 key 在 agent 持续运行期间可继续使用；需立即停止使用时手动卸载对应 key，勿清除其他工具的密钥。升级后需通过新版本重新加载一次，才能移除旧版已写入 agent 的到期时间。

## 备份与恢复

- 完整备份必须能读取并验证所有已引用内容。损坏或缺失时不会用空列表代替，也不会绿色报告完整成功。旧不完整备份被拒绝时，保留原文件；不要删除唯一原库。
- 备份包括账号密码及历史、TOTP、SSH资料、文件、笔记/图片，以及寄存记录/取回内容密钥。远端寄存文件本体和已经过期的远端资料不因此获得永久备份保障。
- 导入或恢复之前，现用库会留下 `backups/security-<UUID>` 加密恢复点，可用原凭据打开。恢复点也包含秘密，应像保险库一样保护；它不是离机备份，不能抵御整盘故障。
- 当前无法完整验证的损坏库不会被恢复流程直接覆盖。应先保留整目录副本再做单独抢救；不能靠忽略错误强行恢复。
- 为避免误删仍被历史/未完成写入引用的附件，即时本地和远端 blob 物理 GC 已暂停。空间会增长；在独立、可验证的保留期回收机制上线前不要手动猜测删除 hash 文件。
- 并发账号改密保留双方密码历史；TOTP 同一条目出现不同种子会拒绝静默合并。先各自导出完整备份，确认哪个绑定有效，再在独立记录中保留另一个有效绑定后重试同步。

## 遗忘与泄露的不同处理

- **只是忘记访问密码**：用恢复码解锁，在设置的恢复凭据区域验证恢复码并设置新密码。此操作保留 MK 和数据内容。
- **保存/轮换恢复码**：本次输入访问密码，准备新码，保存在独立安全位置，输入完整新码确认。未确认前原码继续工作；取消不更换原码。确认成功后重新备份。
- **怀疑旧密码/恢复码或 MK 泄露**：普通改密/轮换恢复码不能撤销持有旧头部与旧凭据的人。他们仍可能恢复同一个 MK，解密以后仍使用它加密的数据。使用安全迁移创建独立新 MK 的保险库副本，确认保存新恢复码后切换；原库保持原状。新库同步默认关闭，应使用新的云端位置与权限再配置。
- 新 MK 不能收回已被复制的旧资料，也不会自动更改第三方网站密码、SSH授权、公有云token或2FA绑定。应分别到这些服务轮换已泄露的实际凭据，并撤销旧设备/授权。高价值账号的验证器可保留在独立安全域。

## 尚需外部验收的边界

- Apple：已做真实模块的两个目标类型检查，但未在 macOS/iOS 正式签名应用上验证 Keychain、录入变化、取消和备份迁移。
- Android：Kotlin编译不等于后台、强杀、输入法/系统剪贴板管理器的真机行为保证。
- 正常并发由条件写入防护；本机保留加密代次/摘要锚，拒绝旧提交回放和同代分叉。主动恶意存储忽略条件写、或新设备/重装丢失本机锚时，需要额外独立可信版本证据，当前不承诺跨重装绝对防回放。
- Windows断电时目录更新耐久性、多设备真实S3服务故障、系统生物识别硬件能力需单独测试。没有把单元测试通过表述成完整安全认证。
