# 首次使用引导 UI 优化与验收

日期：2026-11-15。范围：引导页面布局、动画选项联动、主题预览与对应测试；未更改后端保存、防截图或保险库逻辑。

## 复现与修复

用户截图中的问题已复现。修复前新增布局测试在 980×620 下失败：主按钮实际约 56.5×26.1px；整个引导区域滚动，使标题与步骤一起离开可视范围。

修复内容：

- 标题、步骤导航、底部操作栏各有独立布局位置，只有 `.ob-content` 内部滚动，避免全页滚动和底栏覆盖设置内容。
- 桌面主按钮至少 100×40px，触控操作至少 44px 高；默认 980×620 体验页（未展开额外设置）可完整显示，包括“更多启动偏好”。
- 启动动效和解锁动画各自分组，预览按钮位于对应设置旁；关闭动画时，相关预览与风格控件禁用，保留原风格选择。
- 切换步骤在新内容渲染后回顶；展开 / 折叠设置、缩放窗口不会让标题、步骤或按钮随内容滚走。
- 主题卡片补充窗口内容示意；深色 / 黛蓝预览同时覆盖标题栏，仍只是草稿预览，不写正式主题偏好。
- 手机使用顶部步骤条；窄屏将“隐私与安全”步骤短名改为“隐私安全”，避免单字换行。

## 验收证据

- [布局自动化结果](layout-verification.json)：7 组尺寸与语言，逐页覆盖 3 步、展开 / 折叠、滚动到底、窗口改变、三种主题、键盘与触控操作。检查标题与步骤坐标不变、底栏完整可见、主按钮未被遮挡、末项可滚动到达、无横向及根页面溢出。
- [真实 Windows 窗口结果](native-layout-verification.json)：通过系统 UI Automation 滚动现有独立验收窗口，确认标题 / 导航 / 操作固定、禁用动画预览不可操作；通过截图人工复查。检查前后用户草稿配置文件 SHA256 一致，没有重置用户选择。
- 现有 `scripts/test-onboarding-ui.cjs` 的 14 组交互回归全部通过，涵盖保存、跳过、恢复、错误状态等。
- `npm run build` 通过，167 项前端单元测试通过；变动的 TSX lint 无错误，TitleBar 的既有 effect 警告保留。
- 本轮仅 UI 变更，未重复跑 Rust 全量测试。既有后端测试记录见项目实施记录。

验收中两次发现默认体验页底部披露项离底栏过近，继续压缩冗余留白并复验至通过。实际查看了默认桌面、最小桌面、手机 320 / 390、英文和深色截图，而非仅以脚本退出码判断。
