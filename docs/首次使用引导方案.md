# 首次使用引导方案与页面设计

状态：已于 2026-11-15 批准实施。下文保留评审时的方案与取舍；实际实现及验证结果见《首次使用引导实施记录》。

调研基线：`dev` 分支 `322f6c3`。正式采用三步方案，一页快速设置仅保留作设计比较。

## 1. 本次要解决的问题

新用户在选择、创建或恢复工作空间之前，先知道御钥师如何展示内容、何时锁定，以及哪些操作会影响日常使用。设置应当有解释、有推荐值、可以调整，不要求新用户先理解 Git、加密算法或云同步。

明确采用用户提出的截图规则：**全新本机配置默认不启用截图防护；引导中的“开启截图与录屏防护”默认勾选；只有用户确认保存后，才把选择变为实际设置。**

引导是本机应用层的偏好设置，不创建保险库，不读取现有密钥，不要求提前输入访问密码。

## 2. 推荐流程与备选方案

推荐三步引导：

1. **使用体验**：主题、启动动效、解锁动画与预览。
2. **隐私与安全**：截图防护、离开时锁定、剪贴板清理；展开“更多隐私设置”了解二次验证与账号掩码。
3. **确认设置**：列出选择及其影响，点击“保存并继续”，成功后进入原有的创建 / 恢复 / 打开工作空间入口。

随后仍按现有顺序创建保险库：工作空间位置 → 访问密码 → 保存恢复密钥 → 验证恢复密钥 → 完成。移动端继续使用应用沙箱，不新增目录选择。

创建或恢复完成后，提供一次可跳过的“开启 Windows Hello / 指纹 / 面容”提醒。操作成功才标记已开启。

备选是**一页快速设置**：集中显示核心选项，用一张页面完成确认。适合熟悉产品的人，但安全说明容易被略过，手机页面也更长。因此建议正式采用三步方案；一页方案只用于比较，不同时叠加两套引导。

预计时长文案用“几项设置，随时可改”，不承诺未经实测的完成秒数。避免“安全评分”“已全面防护”等不可验证的描述。

## 3. 哪些设置值得让用户首次就知道

| 设置 | 当前实现 / 当前新配置默认 | 引导建议值 | 首次是否出现 | 用户需要知道什么 |
| --- | --- | --- | --- | --- |
| 截图与录屏防护 | `allow_screenshots=false`，当前实际默认防护开启 | **新配置实际关闭；草稿默认勾选开启** | 主区，优先说明 | 开启后可能影响截图反馈、投屏和远程协助；不是绝对防泄漏承诺 |
| 空闲自动锁定 | 15 分钟 | 草稿推荐 5 分钟；可选 1 / 5 / 15 / 30 分钟 / 不自动锁定 | 主区 | 更短更安全，也会更频繁打断工作；选择“不自动锁定”时出现温和的说明 |
| 锁屏 / 休眠时锁定 | 已开启 | 开启 | 主区 | 离开电脑后保护当前会话；按系统实际检测能力显示“锁屏与休眠”或“休眠” |
| 复制机密后清理剪贴板 | 20 秒 | 20 秒；可选 10 / 20 / 60 秒 / 不自动清理 | 主区 | 仅针对应用复制的机密；若剪贴板已被其他内容替换，不覆盖用户新内容；不宣称可以抹掉所有系统历史或外部同步副本 |
| 查看 / 编辑机密的验证有效期 | 5 分钟 | 草稿推荐 1 分钟；可选每次 / 1 / 5 分钟 | “更多隐私设置” | 这与“空闲锁定”和“开机免验证”是三回事；验证通过后短时间内再次查看或编辑可免重复输入 |
| 账号中间字符掩码 | 开启，头尾各保留 3 位 | 开启 | “更多隐私设置” | 列表更适合旁人可见的场合；密码、密钥的保护不应随账号掩码开关一起被关闭 |
| 剪贴板感知克隆 | 关闭 | 关闭 | “更多隐私设置”，明确选择 | 开启才观察剪贴板中的仓库地址并提示；不是清理剪贴板功能，不因选择其他推荐设置而被自动开启 |
| 启动动画 | 未发现独立启动动效开关 | 新增简短启动动效，草稿勾选；建议不超过 0.8 秒 | 使用体验 | 首次引导前不播放强制动效，保存后下次启动生效；不增加人为启动等待，允许跳过，遵循系统减少动态效果 |
| 解锁动画 | 已开启，赛博 / 经典 / 极简三种，默认赛博 | 草稿开启，推荐极简；保留另外两种选择 | 使用体验 | 只在解锁完成后播放，可独立关闭并预览；关掉动效不改变验证规则 |
| 界面主题 | 经典蓝紫；另有冷萃深色、沉稳黛蓝 | 保留现有经典蓝紫推荐 | 使用体验 | 预览即时改变引导外观，未保存不改变正式设置 |
| 随系统登录启动 | 关闭 | 关闭 | 使用体验的“更多启动偏好” | 仅启动应用，不等于自动解锁；系统写入失败要明确反馈 |
| 关闭窗口时的行为 | 尚未选择时询问 | 保留首次关闭询问 | 不增加首屏负担 | 关闭 / 后台驻留的差别在首次关闭时说明更合适 |
| 生物识别解锁 | 关闭；启用需要已解锁保险库和访问密码 | 创建 / 恢复后推荐，用户主动授权 | 后置独立提醒 | 绑定本机，不能代替恢复密钥，也不能迁移到其他设备；失败不阻碍密码登录 |
| 生物识别查看机密 | 关闭；现有启用流程会同时开启此项 | 在后置提醒中明确告知联动，允许单独调整 | 与生物识别一起 | 避免用户只同意快捷解锁，却不知道查看密码也可使用同样验证 |
| 开机免验证天数 | 0，关闭 | 保持关闭 | 创建后介绍，设置页选择 | 允许一段时间内静默解锁，风险和便利程度明显高于指纹；不与“自动启动”合成一个开关 |
| 指纹取回 TOTP 原始密钥 | 关闭 | 保持关闭 | 高级安全设置 | 属于导出根秘密的高敏操作，不作为首次引导的普通推荐项 |
| 严格模式 / 密钥落盘 | 密钥 / 身份级选项 | 进入导入或生成 SSH 密钥时决定 | 不放初始引导 | 需理解终端、agent、备份与恢复代价，提前询问容易误选 |
| 自动更新检查 | 开启 | 保留 | 可在后续设置查看 | 不把普通更新检查等同于自动下载安装或遥测同意 |
| 云同步、网络代理、密码历史数量、附件策略 | 已有对应设置 | 保留现有值 | 进入对应功能时设置 | 依赖用户使用场景，不适合全部塞进首次引导 |

除截图初始值是本次明确要求外，其余“推荐值”仅在用户保存引导后应用，不顺带重置老用户配置。5 分钟锁定、1 分钟机密验证是本方案建议，仍待评审。

## 4. 截图防护：默认、草稿和生效必须分开

界面一律使用正向语义：**开启截图与录屏防护**。后台原字段是反向语义，映射为 `allow_screenshots = !screenProtectionEnabled`，不要因为勾选而把“允许截图”写成 true。

| 场景 | 实际防护 | 页面呈现 | 后续行为 |
| --- | --- | --- | --- |
| 全新启动，尚未进入引导 | 关闭 | 没有假装已开启的盾牌状态 | 不改变系统捕获行为 |
| 第一次看到安全页 | 仍关闭 | 推荐勾选；提示“当前未开启，保存后生效” | 勾选只是草稿 |
| 用户取消勾选 | 仍关闭 | 提示“保存后保持关闭” | 尊重选择，无反复弹窗 |
| 保持勾选并“保存并继续” | 保存并尝试应用开启 | 保存中禁止重复提交 | 成功后进入工作空间入口 |
| 取消勾选并保存 | 关闭 | 确认页显示“关闭” | 不偷偷改回推荐值 |
| “稍后设置” | 维持实际值；全新用户仍关闭 | 轻提示“可在设置中调整” | 进入原工作空间入口，不应用任何尚未保存的草稿 |
| 保存失败 | 显示已保存 / 未保存的真实状态 | 留在确认页，给出失败项和重试 | 不标记引导完成、不带着未说明的部分成功继续 |
| 退出应用，下次再开 | 保留实际配置，恢复草稿与步骤 | 勾选仍是之前选择 | 不把中途退出等同于“稍后设置” |

**应用时机**：必须在输入访问密码、展示恢复密钥等敏感步骤之前，完成用户选择的保护应用。恢复密钥页面不因截图防护而丢失备份途径：继续提供原有保存 / 复制及验证，提醒用户离线妥善保存；不要为了让用户截图而临时自动关闭保护。

**以后修改**：已开启后，在普通设置页关闭防护应立即反映真实状态；若需要二次认证，放在实现阶段结合现有安全规范明确，不在原型中伪装已存在此验证。

## 5. 平台能力不能用同一句话承诺

- Windows / Android：当前代码有窗口捕获排除 / `FLAG_SECURE` 实现。可以显示推荐勾选，但文案用“减少系统截图、录屏捕获应用画面的风险”，不保证拦截所有第三方录制手段或外部拍摄。
- macOS：当前代码调用窗口 sharingType；其在不同系统版本和捕获接口上的效果必须实测。未确认能力时显示“防护效果受系统版本影响”，不单凭枚举 `exclude` 宣称已全面拦截。
- iOS：当前能力为后台内容遮罩及截屏提示。命名为“后台预览保护”，明确“无法阻止系统截屏”，不能放一个看似能禁止截屏的开关。
- Linux：现有能力为 unsupported。显示说明并禁用防截图选项，不保存一个无法兑现的“已开启”状态；仍推荐自动锁定与机密掩码。

建议后续接口区分“用户期望状态、平台能力、应用结果”。目前 `screen_protect::apply()` 没有返回应用结果，Windows 实现也未检查 API 返回值；不能把配置写盘成功等同于操作系统已经成功实施防护。

## 6. 首次判断、老用户与异常

### 本机引导状态

建议在本机 AppConfig 中新增带版本的状态：`not_started / in_progress / completed / skipped / legacy`，以及 `onboarding_version`。草稿仅包含偏好，不放密码、恢复密钥或云端凭据。

- 真正全新本机配置：初始 `allow_screenshots=true`，引导草稿 `screenProtectionEnabled=true`；这里两个 true 含义相反，必须通过映射层隔离。
- 引导完成后创建另一个工作空间：不重复引导，因为这是本机偏好。
- “稍后设置”：记 skipped，启动时不反复强制弹出；设置页提供“重新查看初次使用引导”。
- 未保存时崩溃 / 关闭：记 in_progress，恢复步骤和草稿；实际防护仍按保存配置。
- 换设备、恢复云保险库：先按新设备能力完成本机引导；不把另一台机器的动画、防截图、指纹或自启动状态强制同步过来。
- 已有用户升级：保留配置，不把所有旧用户重置为允许截图，不强制重跑完整引导。
- 首次启动发现已有本机配置或已绑定工作空间：按老用户处理，不依据“尚未解锁”或“某个配置字段缺失”判断为初次安装。
- 卸载重装但保留配置：仍视为已有本机用户。程序无法可靠判断安装次数，因此产品触发条件应写“此设备首次使用 / 全新本机配置”。

### 旧配置缺字段的迁移

不能只把 `#[serde(default)]` 的布尔默认值和 `AppConfig::default()` 一起简单翻转：旧配置缺 `allow_screenshots` 时，历史行为是防护开启，应保留此语义；只有**确认配置文件不存在的新建配置**才默认允许截图。

建议采用版本化迁移或旧配置 DTO / 原始字段存在性检查，并让 UI 从后端状态派生，不另写互相矛盾的前端默认值。配置损坏或读取失败不等于“新安装”，应显示恢复 / 重试路径并使用已有明确的安全回退策略。

窗口首次显示前应先区分配置来源：新用户按新默认值显示，老用户按已保存状态应用保护后再显示。不能先统一允许截图、等异步加载后才恢复老用户的防护，避免启动时短暂暴露原本要求保护的内容。

### 保存协议

推荐一条后端“提交引导偏好”命令：校验参数 → 保存目标配置及提交进度 → 执行运行时应用 → 返回各项结果 → 全部成功才完成引导。自启动等系统操作和 UI 本地偏好不是真正单个磁盘事务，需定义部分失败、补偿、重试和回读流程，不能声称天然原子。

提交期间禁用按钮；后端使用本机互斥与草稿版本 / 提交标识处理重复提交。调用结果未知时先回读状态，不能自动把操作重放。主题 / 解锁动画现有 localStorage 与后端配置的分离要在实现阶段处理：可迁入统一偏好持久化，或明确提交回执与失败恢复；不要仅前端记一个 completed 就认为全部保存成功。

## 7. 页面与交互说明

- 沿用御钥师经典蓝紫、冷萃深色、沉稳黛蓝的视觉语言，不改变主应用导航结构。
- 桌面采用左侧简洁步骤导航、右侧设置主体；手机改为顶部进度与单列内容。页面可随窗口缩小自然排布，关键操作不依赖悬停。
- 防截图推荐项用复选框，明确区别于“点击立即生效”的开关；旁边有“推荐”标记与状态说明。
- 第一步提供启动动效预览、解锁风格选择；预览只在用户点击时播放，不自动循环。
- 第二步让自动锁定、锁屏保护、剪贴板清理常驻；二次验证、掩码与剪贴板感知放在折叠区，避免一次问十几个问题。
- 第三步展示设置摘要，注明哪些在保存后即时生效、哪些下次启动生效；保留“返回修改”。
- “稍后设置”不叫“使用默认值”，避免用户误以为会使用推荐勾选。跳过后保留真实出厂值。
- 保存按钮文案是“保存并继续”；接下来的创建 / 恢复入口由用户选择，不在同一按钮中偷偷创建保险库。
- 生物识别只是后置推荐，不在前置步骤用一个无效的“已开启指纹”开关占位。
- 文案提供中文和英文；状态文字不能仅依赖红绿、盾牌颜色或动画传达。

设计稿是静态数据的交互预览，不连接 IPC、不保存真实配置、不访问剪贴板、不申请系统权限、不创建真实保险库。原型的动画仅展示时长与过渡意图，不代表最终动效资产。

## 8. 实施顺序（批准方案后再执行）

1. 配置与迁移：区分全新 / 老配置 / 损坏，增加引导状态；先补边界测试。
2. 截图初始行为：统一 Rust 默认、早期窗口初始化、前端失败回退及各平台能力展示；保留旧配置语义。
3. 偏好草稿与提交协议：支持恢复草稿、跳过、部分失败回读与防重复提交。
4. 桌面引导：三步流程、动效预览、推荐选项与确认页，接入原工作空间向导。
5. 移动端适配：复用状态模型，按平台能力显示；保持沙箱工作空间机制。
6. 创建后生物识别提醒：单独授权，不阻塞密码使用；明确查看机密的联动行为。
7. 回归与文档：按下列验收矩阵逐项验证，再考虑合并。

## 9. 验收矩阵

1. 全新配置打开引导之前、在推荐框已勾选但未保存时，仍允许截图。
2. 保持勾选保存后，在进入密码 / 恢复密钥页面前应用防护；取消勾选或跳过后保持关闭。
3. Windows / Android 实测捕获结果；macOS 分版本记录；iOS / Linux 文案不作虚假承诺。
4. 上一步、关闭重启、崩溃重开均不丢失草稿；跳过、已完成和已有用户不反复强制弹出。
5. 老配置显式开 / 关、缺字段、配置损坏、保留配置重装等分支分别验证，不能统一归为首次安装。
6. 保存失败 / 重复点击 / 重复 IPC / 未知结果不重复写系统设置，不错误标记完成。
7. 自动锁定与机密验证有效期分别生效；锁屏能力不支持时正确降级。
8. 自动清理剪贴板不覆盖后来复制的内容；感知克隆保持默认关闭。
9. 关闭启动 / 解锁动画，或系统减少动态效果开启时，不出现强制动效与人为等待。
10. 保存后接入创建、恢复及已有工作空间路径；不丢失现有恢复密钥验证步骤。
11. 生物识别仅在保险库就绪后启用；取消或失败不影响密码登录。
12. 桌面 980×620、最小窗口 840×520、手机 360 / 390 宽、深浅色和键盘操作可用；最终功能测试须在真实 Tauri 环境进行。

## 10. 关键源码依据

- `app/src/App.tsx`：当前未初始化时直接进入 `InitWizard`，尚无应用级前置引导。
- `app/src/shared/hooks/useInitModel.ts`：创建与恢复的现有步骤、移动端固定工作空间逻辑。
